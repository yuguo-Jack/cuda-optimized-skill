# HCU 算子优化报告

## 1. 问题、接口与代码导航

原始需求、数学语义、输入输出/布局/stream/数值契约；工程目录→入口→分派→实际kernel；目标场景与性能指标。

## 2. 环境和证据来源

GPU/gfx/wave、驱动/DTK、AICC或其他编译器绝对路径及版本、Torch/Triton/库SHA、父仓子模块gitlink、构建命令；实际参考的源码/文档/实验出处，引用知识库时再附ID/SHA/页码；历史结论与本轮实测分开。

## 3. 基线与测试矩阵

baseline/reference SHA与独立性；case/seed/dtype/shape/stride/mask/路由分布；全部输出、容差、race/越界/确定性检查的实际状态；未覆盖项及原因。

记录实际有效的数值验收政策：输入/累加/输出精度、atol/rtol、特殊值、舍入/饱和、是否要求逐位/确定性；若算法变换被允许，说明用户目标和值域前提。before/after 的计时范围、缓存/同步政策与测试输入保持一致。

## 4. 瓶颈与修改

准确kernel/dispatch、工具与指标公式/单位/范围、原件路径；可证伪假设；修改文件/符号/代码解释；为什么改、适用条件与预期证据。

遇到瓶颈时必填：触发现象、实际采集命令/工具版本、XCompute或等效分析结果、关键指标/时间线→瓶颈判断→下一项实验、修改前后同口径对照。工具/权限受阻则列出原因与待采命令，诊断状态写未完成。

分别引用 best_input 与 champion 的本次 profile 记录和原件，注明重新采集/失败尝试；`collected` 不代表已解读，`degraded` 需结合 reason 区分原件缺失与尚未转换。不同工具或指标组不能直接拼成前后百分比。

## 5. 变体、消融与结果

每个变体方法组合和超参数；真实样本/均值/中位数/p90/CV、工作负载加权/回退检查；编译/正确性/OOM失败记录。kernel-only、compile/autotune、端到端分别比较。消融是否正确、机制是否核实、仍未验证的方法。

## 6. 结论、边界与回退

选中的实现及其支持范围，收益与噪声，热点是否转移，失败条件/回退，待硬件验证/待补工具/权限；不可将静态复核写成HCU实测。报告和原始产物在当前任务工程中的路径。

真实工程集成验收：生产分派是否命中、fallback、工程单测/多 rank/stream、端到端时间、workspace/峰值显存、JIT/冷启动成本。说明停止原因、阶段失败与后续修复，区分 best 晋级、方法归因和工程验收三个结论。
